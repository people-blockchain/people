# Вход через Gmail/email и смена страны — что сделать в Vercel/Web3Auth

Алекс, это шаги для тебя в панели Vercel и (если понадобится) в дашборде Web3Auth.
Код уже поправлен и покрыт тестами (см. итог внизу) — но два момента может
закрыть только владелец аккаунта.

## 1. Переименовать `AUTH_UR` → `AUTH_URL`

В Vercel (Project Settings → Environment Variables, production) сейчас есть
переменная **`AUTH_UR`** — это опечатка, вместо `AUTH_URL`. Из-за неё
`AUTH_URL` фактически не задан.

Сегодня это не ломает вход (код использует запасной `SITE_URL`,
`https://www.peopleblockchain.network`, если `AUTH_URL` пуст), но лучше
исправить, чтобы не было сюрпризов в будущем:

1. Vercel → Project → Settings → Environment Variables.
2. Удали `AUTH_UR`.
3. Добавь `AUTH_URL` = `https://www.peopleblockchain.network` (production).
4. Redeploy (Deployments → ⋯ → Redeploy на последнем production-деплое).

## 2. Задать `PEOPLE_WALLET_VAULT_SECRET`

Сейчас эта переменная не задана, и код автоматически использует `AUTH_SECRET`
как запасной вариант (это намеренно сделано в #192, вход не ломается). Но это
закрывает аудиторскую находку M02-2 (утечка `AUTH_SECRET` не должна означать
утечку ключей шифрования кошельков) — рекомендуется закрыть:

1. Сгенерируй секрет: `openssl rand -base64 32`.
2. Vercel → Environment Variables → добавь `PEOPLE_WALLET_VAULT_SECRET` (production) с этим значением.
3. Redeploy.

Существующие кошельки (зашифрованные старым ключом на основе `AUTH_SECRET`)
автоматически мигрируют на новый секрет при следующем успешном входе —
ничего руками переносить не нужно, это уже в коде и покрыто тестами.

## 3. Если вход через Gmail или email снова откажет — как диагностировать

В код добавлено логирование (раньше при отказе входа сервер не писал вообще
ничего, кроме общей ошибки `CredentialsSignin` — невозможно было понять,
почему). Теперь при следующем отказе открой Vercel → проект → Logs (или
`vercel logs www.peopleblockchain.network --since 1h`) и ищи одну из строк:

- `[auth] web3auth idToken verification failed <причина>` — токен Web3Auth не
  прошёл проверку (истёк, подпись не сошлась, недоступен JWKS-эндпоинт
  Web3Auth). Обычно значит — просто повторить вход; если повторяется
  стабильно, проверь `NEXT_PUBLIC_WEB3AUTH_CLIENT_ID` /
  `NEXT_PUBLIC_WEB3AUTH_NETWORK` в Vercel и соответствие Client ID в
  дашборде Web3Auth (Sapphire Mainnet).
- `[auth] web3auth sign-in refused: email already bound to a different
  identity under this verifier` — это значит, что для одного и того же
  email Web3Auth вернул два РАЗНЫХ `verifierId` при входе через Gmail и через
  email-код. Код намеренно отказывает в таком случае (не сливает две разные
  идентичности в один аккаунт без проверки) — **это нужно чинить в дашборде
  Web3Auth**: Settings → Auth Connections — Google и Email Passwordless
  должны быть настроены как под-провайдеры ОДНОГО и того же проекта/
  verifier'а (а не как два независимых). Если там всё уже так настроено и
  сообщение всё равно появляется — пришли нам точный текст лога, это будет
  повод разбираться дальше в коде, а не в дашборде.

## 4. Проверь в дашборде Web3Auth (Sapphire Mainnet, твой проект)

Redirect/Origin whitelist должен содержать ровно:

- `https://www.peopleblockchain.network`
- `https://www.peopleblockchain.network/login`

(сайт отдаётся на `www`, apex-домен 308-редиректит на `www` — см.
`src/lib/site.ts`). Если в дашборде стоит только apex без `www`, добавь оба.

## Что уже исправлено в коде (эта ветка)

- **Смена страны у уже зарегистрированного фаундера.** Форма редактирования
  страны ошибочно писала выбранное значение в тот же `localStorage`-ключ, что
  и виджет выбора страны ДО регистрации (`ppl_founders_country_choice`) — в
  том числе когда сохранение на сервере ещё не подтвердилось или вовсе
  провалилось (rate limit и т. п.). При нескольких аккаунтах в одном браузере
  это могло "протаскивать" страну одного аккаунта в авто-регистрацию
  следующего — отсюда ощущение, что смена страны "ничего не делает", и что
  видно меньше стран, чем реальных аккаунтов. Сервисный код обновления страны
  (`updateFounderCountry`) был и остаётся корректным — баг был только в этой
  клиентской форме. Исправлено и покрыто regression-тестом
  (`scripts/founders-country-edit-persistence.spec.mjs`).
- **Диагностика входа.** См. пункт 3 выше — раньше отказ входа не оставлял
  вообще никакого следа в логах.

## Как проверить после деплоя

1. Зайди на `/founders` из аккаунта, где страна уже сохранена (например,
   Georgia), открой селектор страны в успешном блоке, выбери другую страну.
   Должно появиться "Страна обновлена." и значение должно остаться новым
   после обновления страницы (F5).
2. Если раньше вход не получался — попробуй снова (Gmail и email по
   отдельности) и, если опять не получится, пришли время попытки, чтобы
   сверить с логами Vercel (пункт 3).
