# Исправления аудита сервиса, 2026-09-30

Статус: реализация в ветке `codex/security-hardening`, проверки перечислены ниже.
Независимый внешний аудит не заменён. На VPS эти изменения не установлены.

## Исправления

- Отрицательные и некорректные суммы/комиссии отклоняются до записи; неуспешная
  транзакция и блок не оставляют частичного состояния. Приём в mempool не создаёт
  аккаунты и не начисляет комиссии. Новые заявки сохраняются при асинхронной сборке.
- Блоки проверяются по подписи выбранного производителя, chainId и версии 2;
  bootstrap identity закреплена публичным адресом. Награды эпохи входят в общий
  переход состояния у производителя и принимающих нод. Изменения рейтингов по
  локальным часам больше не меняют консенсусное состояние вне блока.
- Подписанные транзакции привязаны к сети во всех клиентах. Treasury, burn,
  pending fees, network config и применённые доказательства включены в state root.
- Доказательство double-sign содержит два подписанных конфликтующих блока;
  повторная подача той же пары не штрафует повторно. HTTP report направляет
  доказательство в транзакцию вместо локального изменения stake.
- Дробные eligible комиссии распределяются по одобренному Model A в микро-PPL.
  Единицы Growth ledger/claims описаны в PROTOCOL-DECISIONS.md.
- Контекст EVM изолирован между асинхронными вызовами; неизменённые балансы не
  округляются при сохранении EVM. Настоящие адреса переводов проверяются строго.
- Gossip требует handshake своей сети, ограничивает размер WS/распаковки gzip,
  количество блоков, peer book и cache; некорректный блок не попадает в обработчик.
- Повреждённый snapshot вызывает отказ запуска вместо тихой замены на genesis;
  сохранение индексирует все новые блоки и подтверждает высоту после успешной записи.
- Компилятор Solidity вынесен в дочерний процесс с timeout, пределом heap и двумя
  слотами. Только реальные `.sol` внутри OpenZeppelin разрешены для импортов;
  traversal и symlink за пределы библиотеки отклоняются. Секреты окружения не
  передаются дочернему процессу. Это ограничение импортов, не ОС-песочница.
- AI compose не помечает сгенерированный контракт как прошедший аудит. RPC proxy
  имеет timeout; API доверяет forwarded IP только от локального reverse proxy.

## Проверка

Регрессии: `packages/core/src/security-regressions.test.ts`,
`storage-security.test.ts`, `packages/p2p/src/security.test.ts`,
`website/scripts/compiler-security.test.mjs` и обновлённые существующие тесты.
GitHub workflow добавлен в корневой `.github/workflows/ci.yml`; вложенный файл
PEOPLE Network оставлен как историческая конфигурация.
Полный прогон: монорепозиторий `npm run build`, `npm run typecheck`, `npm test`,
`npm run ci:smoke`; сайт `npm test`, `npm run build`.
Smoke использует три локальных процесса и временные данные, проверяет catch-up,
рестарт и совпадение блока/stateRoot на общей высоте.

## Обновление существующей сети

1. Ревью → PR → merge main → записать согласованный SHA.
2. До остановки сохранить резервную копию существующей цепочки и секретов по
   согласованной операторской процедуре. Не копировать живой LevelDB как надёжный backup.
3. Отдельно согласовать миграцию v1→v2 или запуск новой тестовой цепочки. Автоматической
   миграции нет; никогда не удалять DATA_DIR для обхода проверки совместимости.
4. Создать новый отдельный bootstrap-ключ в секретном окружении seed, раздать только
   публичный `BOOTSTRAP_ADDRESS`. Сверить chainId, genesis/config и тарифы на всех нодах.
5. Развернуть согласованный SHA и проверить подписи, общие hash/stateRoot, рестарт.
6. Только после этого переключать публичный домен и проверять TLS/доступность.

Сайт должен работать за reverse proxy, перезаписывающим `X-Real-IP`.
Только в этой конфигурации включать `TRUST_PROXY_HEADERS=1` для передачи IP в ноду;
без неё используется общий лимит локального прокси. Ноду не выставлять напрямую.
`BOOTSTRAP_PRIVATE_KEY` не копировать follower-нодам; faucet остаётся тестовым.
